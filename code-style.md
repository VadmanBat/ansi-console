# Стиль программирования

### 1. Общие принципы:

- код должен быть **читаемым**, затем **производительным**;
- простота важнее хитрости;
- алгоритмы и структуры данных выбираются с оптимальной асимптотикой и минимальными накладными расходами;
- избегать ненужных абстракций.

### 2. Организация проекта

#### Структура папок

```
project-root/
├── include/            # публичные заголовки (.h / .hpp)
├── include/constants/  # вынесенные константы (.hxx)
├── src/                # реализации (.cpp)
├── tests/              # тесты
└── CMakeLists.txt
```

#### Расширения файлов:

- `.h`   — только объявления классов/структур/функций (без определений);
- `.hpp` — шаблонные классы или классы, полностью реализованные в заголовке;
- `.hxx` — файлы только с константами, enum-классами, constexpr-значениями;
- `.cpp` — реализации функций и методов.

#### Название файлов:

- **kebab-case**: `my-class.h`, `utility-functions.cpp`, `global-constants.hxx`

### 3. Система именования

| Элемент                             | Стиль           | Пример                              |
|-------------------------------------|-----------------|-------------------------------------|
| Классы / структуры                  | PascalCase      | `class ImageProcessor`              |
| Методы класса                       | camelCase       | `processImage()`                    |
| Переменные (локальные и глобальные) | snake_case      | `int pixel_count`                   |
| Свободные функции                   | snake_case      | `int calculate_sum()`               |
| Константы                           | SNAKE_UPPER     | `const int MAX_BUFFER_SIZE = 1024;` |
| Enum-классы                         | PascalCase      | `enum class ColorSpace`             |
| Значения enum                       | PascalCase      | `ColorSpace::RGB`                   |
| Макросы (если нужны)                | SCREAMING_SNAKE | `#define DEBUG_MODE`                |

### 4. Пробелы и форматирование:

- отступы: **4 пробела** (не табы);
- пробелы вокруг бинарных операторов: `a + b * c`, `x = y + 1;
- пробелы в шаблонах:
  - в **типах данных** — с пробелами: `std::vector <int>`, `std::map <std::string, int>`;
  - в **вызовах шаблонных функций** и объявлениях — без пробелов: `std::make_unique<MyClass>(args)`,
  `template<typename T> void func(T value)`;
- пробел после запятой: `func(a, b, c)`;
- пробел после ключевых слов: `if (condition)`, `while (true)`;
- максимальная длина строки: **120 символов**.

#### Ссылки и указатели:

- `&` и `*` прилипают к типу (без пробела перед ними);
- примеры:
```cpp
const std::string& password;
const MyClass* ptr;
int& ref;
void func(const std::vector <int>& items, MyClass* obj);
```

#### Фигурные скобки — One True Brace Style (OTBS) с особым правилом для else

- открывающая скобка `{` всегда на той же строке, что и объявление;
- закрывающая скобка `}` — на новой строке;
- `else` всегда начинается с новой строки после закрывющей скобки `}` предыдущего `if`:

```cpp
void fun() {
    if (condition) {
        do_something(1);
        do_something(2);
    }
    else {
        do_other_thing(1);
        do_other_thing(2);
    }

    if (short_condition)
        single_action();
    else
        single_alternative();
}
```

#### Условия и циклы:

- тело **всегда** начинается с новой строки;
- если тело состоит из **одного** действия — **фигурные скобки не используются**.

### 5. Порядок членов в классе:

- сначала **private** секция (по умолчанию всё private).
- в **private** секции:
  1. Сначала **переменные-члены** (данные).
  2. Потом **приватные функции** (вспомогательные методы).
- затем **protected** (если нужен).
- затем **public**:
    1. Конструкторы/деструктор.
    2. Публичные методы.
    3. Статические методы/переменные.

**Логика**: сверху вниз как в функциональном программировании — сначала данные, потом операции над ними.

Пример:

```cpp
class ImageProcessor {
private:
    // 1. Переменные
    int width;
    int height;
    std::vector <uint8_t> pixels;

    // 2. Приватные функции
    void validateDimensions();
    uint8_t getPixel(int x, int y) const;

public:
    ImageProcessor(int w, int h);
    ~ImageProcessor();

    void loadFromFile(const std::string& path);
    void applyFilter();
};
```

### 6. Пространства имён:

- **в заголовочных файлах** — запрещено `using namespace ...` и `using std::...`. Только полная квалификация;
- **в .cpp** — после всех `#include` можно selective using только нужных элементов:

```cpp
using std::vector;
using std::string;
```

### 7. Структуры данных и производительность:

- простейшая структура с минимальными накладными расходами;
- `std::vector <int>` — только при динамическом размере или передаче ownership.

### 8. Заголовочные файлы:

- `#pragma once` (предпочтительнее) или классические guards;
- минимизировать включения, использовать forward declarations.

### 9. Примечание:

- данный стиль применяется к основному коду проекта;
- если идёт разработка специфического кода, в редких случаях, стилем можно пренебречь.
